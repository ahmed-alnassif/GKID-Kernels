# Kesepakatan Kerja & Peta Pekerjaan

Dokumen ini adalah sumber utama aturan kerja dan urutan prioritas. Owner cukup mengetik **`lanjutkan`**; pekerjaan diambil dari item teratas yang belum selesai di bagian *Peta Pekerjaan*.

## A. Aturan kerja

1. **Petakan dulu, kerjakan kemudian.** Semua pekerjaan tercatat di peta di bawah dengan prioritas (P0 tertinggi). Tidak ada pekerjaan di luar peta tanpa ditambahkan dulu.
2. **Tidak ada pekerjaan ganda.** Cek peta, checkpoint, dan run hijau sebelum mulai. Pengulangan cek/test **maksimal 2 kali** (idealnya 1 kali) per perubahan.
3. **Hemat sumber daya.** Gabungkan perubahan kecil dalam satu commit/push yang bermakna; hindari push beruntun yang hanya memicu CI berulang.
4. **CI selektif.**
   - Run yang sudah **hijau** dicatat sebagai bukti keberhasilan (ID run) dan tidak dijalankan ulang.
   - Run **merah**: baca log dulu, cari akar masalah, perbaiki, lalu jalankan **satu** run verifikasi. Tidak boleh "coba-coba" berulang.
   - Re-run hanya bila benar-benar perlu (mis. runner mati sebelum test berjalan).
5. **PR selektif.** Satu PR = satu topik, kecil, berbasis branch tujuan yang benar. Jangan membuka PR antar branch yang tidak punya riwayat bersama (penyebab "This pull is big, showing recent 250").
6. **Rapikan issue/PR/branch** secara berkala; yang tidak perlu ditutup dengan alasan. Tidak wajib segera, tapi tidak boleh menumpuk.
7. **Tidak ada yang terbengkalai.** Pekerjaan sulit boleh ditunda, tetapi tetap tercatat di peta dengan status dan alasan.
8. **Judul workflow harus sesuai isi pekerjaannya.** Ketidaksesuaian dicatat dan diperbaiki.
9. **Checkpoint secukupnya.** Hanya di akhir satu blok kerja yang berarti (bukan setiap langkah), ditulis di bagian *Checkpoint* dokumen ini.
10. **Menjalankan workflow GitHub Actions yang mengompilasi kernel hanya oleh owner** (diperjelas 2026-10-15). Kompilasi kernel lain, misalnya lokal di container sesi, **boleh** dilakukan Claude. Workflow ringan seperti `Validate` boleh berjalan otomatis lewat push/PR. Release, flash, dan penghapusan production guard tetap keputusan owner.
11. **Ruang lingkup: kernel 6.1 saja** (keputusan owner 2026-10-15). Versi 5.10/5.15/6.6/6.12 diabaikan: tidak dipin, tidak dilaporkan, dan tidak dikerjakan. Sejak 2026-10-16 form build **dikunci di 6.1** (permintaan owner) dan langkah prepare menolak versi lain; kode lama untuk versi lain dibiarkan.
12. **Issue tidak pernah dihapus.** Issue ditutup hanya bila kriteria selesainya terpenuhi (keputusan owner 2026-10-15): #19 setelah uji perangkat lolos dan opsi KSUN+SUSFS dibuka; #3 setelah verifikasi Manager APK di perangkat; #2 setelah data ccache dari build alami berikutnya.
13. **Hapus/gabungkan dikumpulkan jadi satu** (keputusan owner 2026-10-16). Pekerjaan "hapus" atau "gabungkan" berikutnya tidak lagi dibuat sebagai workflow sekali pakai terpisah. Hapus ref atau run (tag, branch, riwayat run) dijadikan pilihan di **satu** workflow hapus milik owner (kini *Hapus log run lama*), cek dulu lalu `HAPUS`. Hapus file atau kode yang tidak dipakai dikerjakan Claude lewat PR biasa.
14. **"Yang baru" di rilis** (permintaan owner 2026-10-16). Setiap perubahan yang terasa bagi pengguna kernel diberi baris `Baru: …` atau `Diperbaiki: …` (singkat, bahasa Indonesia) **dan** pasangannya `New: …` atau `Fixed: …` (English) di pesan commit squash-nya; bila English terlewat, versi Indonesia yang tampil. Manual Release mengumpulkan baris itu sejak rilis sebelumnya. Untuk rilis yang perlu teks khusus, tulis `docs/whats-new/<tag>.md` (`### Baru` / `### Diperbaiki`). Perubahan CI/dokumen tidak diberi baris itu. Naik versi komponen (kernel, manager, SUSFS, NoMount, BBG, Neutron) **tidak** perlu baris: tercantum sendiri di *⬆️ Diperbarui*.

15. **Checkpoint atas permintaan owner** (permintaan owner 2026-10-16). Bila owner mengetik **`checkpoint`**, Claude langsung menyimpan keadaan kerja, tanpa menunggu blok kerja selesai:
    - tulis satu entri di bagian *E. Checkpoint* dengan format tetap: **Selesai** (apa yang sudah jadi + commit), **Sedang berjalan** (termasuk keadaan di luar repo, mis. build lokal, branch, PR, run Actions), **Berikutnya** (langkah persis, urut), **Menunggu owner** (keputusan/uji HP yang dibutuhkan);
    - perbarui status baris terkait di *C. Peta pekerjaan*;
    - commit + push ke branch kerja saat itu juga (push ke branch kerja tidak memicu CI), lalu laporkan hash commit-nya.
    - **lalu berhenti total** (penegasan owner 2026-10-16: "Jika diminta Checkpoint wajib memberhentikan semua pekerjaan"): tidak ada PR, merge, push, run workflow, komentar atau langkah kerja lain sampai owner meminta lanjut (`lanjutkan` atau perintah kerja yang jelas). Link, laporan atau pertanyaan dari owner **bukan** izin lanjut; jawab saja. Proses lokal yang sudah berjalan (mis. compile) boleh selesai sendiri, hasilnya hanya dilaporkan. Pelajaran 2026-10-16: setelah checkpoint `00d023a`, link run dari owner dianggap izin lanjut — itu salah.

    Sesi berikutnya mulai dari entri checkpoint terbaru (lihat `CLAUDE.md`). Entri lama tidak dihapus.
16. **Kompatibel dulu, flash belakangan** (keputusan owner 2026-10-16: "Tidak usah terburu-buru flashing. Buat dulu kompatibel!"). Build untuk HP (rothko) baru disarankan untuk di-flash setelah bukti kompatibilitas offline lengkap: paritas GKID, gate KMI (sejak D-021 di `cogan17/Xiomi-14t-pro`), compile lokal, dan kalibrasi gate pada kernel yang sudah terbukti boot. Uji lokal di container (staging, compile, cek simbol) bukan flashing dan tetap boleh.
17. **Keputusan PR dan issue didelegasikan ke Claude** (keputusan owner 2026-10-16: "Untuk PR keputusan saya berikan ke kamu full, misalnya merge dan squash. Issue jika butuh dirampingkan lakukan"; "jika ada PR atau issue yang tidak jelas atau tumpang tindih bisa kamu perbaiki"). Claude memutuskan merge/squash, menutup/membuka/merampingkan issue dan memperbaiki yang tumpang tindih, di Cogan dan Xiomi-14t-pro, dengan alasan tertulis di thread-nya. Tetap di tangan owner: run workflow build kernel (A10), rilis dan flash (A16); run workflow boleh dijalankan Claude bila owner memintanya secara eksplisit (2026-10-16: "Jalankan ulang Cogan Rothko Kernel Builder", "Lakukan sampai selesai"). Pelajaran 2026-10-16: repo `cogan17/Xiomi-14t-pro` adalah **repo khusus kernel rothko**, bukan arsip; penutupan yang sempat dibuat atas salah paham itu sudah dibatalkan.
18. **Cogan tidak boleh terganggu** (keputusan owner 2026-10-17: "Yg terpenting perlu dicatat. Cogan repo jangan sampai terganggu!"; latar: W54). Aturan tetap:
    - Cogan = kernel GKI 6.1 **umum** + mesin build-nya. Tidak ada kode, isian form, workflow, patch, lock, artifact atau bukti uji khusus perangkat (rothko atau perangkat lain) di Cogan. Penjaga otomatis: `tests/test_root_matrix.py` gagal bila kode Cogan menyebut `rothko`, `Xiomi`, `TARGET_DEVICE`, `KERNEL_SOURCE=`, `kmi_compat` atau `COGAN_MIRROR_REPO`.
    - Kernel perangkat dikembangkan di repo-nya sendiri dengan **salinan mesin sendiri** (rothko: `cogan17/Xiomi-14t-pro`, branch `rothko-engine`, D-021). Repo itu **tidak menulis apa pun ke Cogan**: tidak push, tidak PR, tidak menjalankan workflow Cogan, tidak memakai cache Actions atau rilis Cogan untuk menulis. Yang boleh hanya **membaca** (sekarang: rilis `cogan-mirror` untuk APK BakaSU spoofed).
    - Arah salinan **satu jalan**: perbaikan umum dibuat di Cogan dulu (PR ke `dev`, berguna untuk GKI umum, tanpa menyebut perangkat), lalu disalin manual (cherry-pick) ke mesin repo perangkat. Tidak ada merge balik dari repo perangkat ke Cogan.
    - Perkembangan Cogan tidak ditahan, dibatasi atau diubah demi perangkat: repo perangkat mengunci commit mesinnya sendiri, jadi perubahan Cogan tidak pernah memecahkan build perangkat.
    - Bila pekerjaan untuk perangkat ternyata butuh mengubah Cogan, berhenti dulu dan tanya owner.
